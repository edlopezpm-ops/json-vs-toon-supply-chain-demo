# Deterministic output validation: validation and diagnosis

Run from the repository root:

```shell
npm ci
npm test
```

Use Node.js 20+ and the committed lockfile. [package.json](../package.json) defines `npm test` as generation followed by `git diff --exit-code` for the two tracked output files.

| Observation | Meaning and next action |
| --- | --- |
| Dependency install fails | Inspect the npm error and lockfile before changing dependency versions; generation has not been validated. |
| Generator fails | Inspect [generate-comparison.mjs](../src/generate-comparison.mjs) and its error; no output agreement is established. |
| Output diff is nonempty | Compare source data, serializer version, formatting, and committed artifacts. Preserve the diff for review. |
| Clean output diff | The regenerated bytes agree with the current tracked baseline; this is reproducibility evidence, not an independent semantic oracle. |

`npm test` writes the two output files before comparing them. Use a clean branch and inspect the diff afterward. If changing the fictional dataset or serializer intentionally, regenerate both files, review the source and output differences together, then commit them in the same PR. Never update generated files simply to suppress an unexplained failure.

The two artifact paths are `output/warehouse-orders.json` and `output/warehouse-orders.toon`. The generator uses fixed source data, including a fixed timestamp; it does not fetch warehouse data or call an LLM.

Character counts use Unicode code points and byte counts use UTF-8. Neither proves model token usage, cost savings, round-trip decoding, or model accuracy. Keep the [walkthrough](../HOW_TO_USE.md) and result descriptions aligned with those limits.

See [change and recovery guidance](change-recovery.md) before merging a correction.
